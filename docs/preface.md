# 序言

## 为什么要学 GPU 驱动

GPU 驱动是图形系统、内核机制和硬件执行模型的交汇点。它既不是纯图形 API，也不是纯硬件知识，而是一套跨越用户态、内核态、总线、内存管理、同步和显示控制的系统工程。

如果你想真正理解一帧图像是如何从应用程序走到 GPU，再从 GPU 输出到屏幕，驱动是绕不开的一层。

## 这份仓库希望解决什么问题

很多 GPU 驱动学习资料要么太碎，要么太偏概念，要么一上来就直接进入复杂驱动源码，导致学习过程很容易失去方向。

这个仓库想做的是：

- 用课程化结构拆开知识点。
- 用 lab 强制建立“可验证的理解”。
- 用 session 复盘、lab 记录和源码路径图沉淀你自己的长期资产。

这里的 `session` 和 `lab` 有明确分工：

- `session` 更像讲义，负责把概念讲清楚，给出源码入口、代码片段和阅读顺序。
- `lab` 更像训练单，负责让你动手画图、追路径、跑命令、读日志，并留下可以复查的证据。

最推荐的节奏是：先读同号 session，带着核心问题进入 lab；做完 lab 后，再回到 session 修正自己的理解。

## 学习目标

完成这套学习后，你应该逐步建立下面这些能力：

1. 理解 Linux 图形栈和 GPU 驱动的整体位置。
2. 掌握 DRM/KMS、显存管理、同步、中断、命令提交这些核心概念。
3. 能读懂典型驱动的初始化和主要数据流。
4. 能把抽象概念落实到源码、日志和实验结果上。

## 学习原则

- 先全局，后局部。
- 先框架，后实现。
- 先简单驱动，后复杂驱动。
- 先画图，再细读代码。
- 每周必须有输出。
- 每个结论尽量对应源码、命令、日志或图示。
- 能运行就运行；不能运行就降级成源码路径追踪，并明确缺少的实验条件。

## 学习环境预期

推荐优先查看 [docs/roadmap.md](./roadmap.md) 里的环境建议与适配范围，再决定使用原生 Linux、QEMU 还是 WSL2 开始这套课程。

## 建议心态

GPU 驱动学习天然会比较陡峭，前几周看不懂复杂驱动是正常的。关键不是一次把所有代码吃透，而是持续建立地图、词汇表、数据流感知和定位能力。

当你知道“这个问题应该去哪个目录看、先看哪个对象、顺着哪条路径往下读”，你就已经跨过了最难的一步。
